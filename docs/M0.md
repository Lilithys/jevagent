# M0 验收标准与场景

## 一句话目标

在《哈利波特：魔法觉醒》里，把一段相对固定的操作在手机上示范一次，之后 jevagent 能**可靠地自己重复**。画面和录制时不一致时，它**停下并说明原因**，不盲点。

"可靠"用下面的场景和次数来衡量。全部通过才算 M0 完成，之后再开始 M1。

## 范围

| 项目 | M0 的约定 |
| --- | --- |
| 设备 | HONOR ELZ_AN00，Android 14，USB 调试；游戏横屏 2376×1152。录制和回放用同一台手机、同一显示分辨率 |
| 输入 | 单指点击、长按、滑动/拖动，都在手机屏幕上操作 |
| 起点 | 你手动把游戏停在录制时的起始画面再开始回放 |
| 判断 | 只判断"画面是否和录制时一致"：每步的锚点，加上结束画面 |
| 不在 M0 | 处理随机弹窗、按画面内容走不同分支、OCR、LLM / Jev、定时运行、多指、iPhone、换机型 |

## 测试场景

挑场景时注意两点：**能回到起点**（才能连续测 10 次），**不消耗资源**（不要包含购买、抽卡、消耗体力的点击）。领取类日常每天只能跑一次，所以单独按天验收。

| 编号 | 场景 | 类型 | 覆盖 |
| --- | --- | --- | --- |
| S1 | 主界面 → 点右上「热销」→ 点左侧「商店」页签 → 点左上返回 → 回到主界面 | 可重复，只浏览 | 点击、页面加载等待、结束画面判断。你 10 月 2 日在 iPhone 镜像上录的就是这条路径的前半段 |
| S2 | 你选一个带滑动或长按的浏览流程（例如打开某个列表，向下滑两次，再返回主界面） | 可重复，只浏览 | 滑动/长按、列表位置变化 |
| S3 | 你选一个真实的每日领取（例如每日免费奖励或活动签到），领完回到主界面 | 每天一次 | 真实任务结果 |

S2、S3 的具体路径由你定，写进下面的验收记录。

## 验收标准

### A. 环境

- **A1** `uv run jevagent check` 认出手机，画面为 2376×1152 横屏，截图平均 ≤ 0.3 秒/帧，列出触摸屏设备。

### B. 录制

- **B1** 录 S1–S3 时，终端实时列出每个手势。报告里每一步的红圈/红线都落在你实际按的位置（逐一目测，落在按钮范围内即可）。
- **B2** 录制中用两根手指操作一次：终端提示已忽略，流程里不多出错误步骤。
- **B3** 录制中按 Ctrl+C 放弃：`data/flows/` 里不留下半成品。

### C. 回放可靠性

- **C1** S1、S2 各从起点运行 `play --times 10`：每条至少 9 次判定成功。并且每次的判定都和你在手机上看到的一致：说成功的确实走完并回到了主界面，说失败的确实出了问题。
- **C2** S3 连续 3 天每天回放 1 次：3/3 判定成功，并在游戏里确认奖励已领取。
- **C3** 单次回放用时不超过录制时长的 1.5 倍（报告里有每步等待时间）。

### D. 出错时安全停下

- **D1** 停在别的界面（不是起点）就开始回放：第 1 步约 5 秒内停止，手机上没有发生任何点击。
- **D2** 回放途中人为打开一个录制时没有的界面（例如手动点开另一个菜单）：在该步超时后停止，后续步骤不执行。报告并排显示失败时的画面和期望的画面。
- **D3** 回放中按 Enter：当前手势松开后停止，游戏里没有残留的按住状态。
- **D4** 回放中拔掉数据线：报错退出，不重试。重新插线后从起点重新开始即可。

### E. 维护

- **E1** 不重录，只用 `edit` 删除一个误触步骤、关闭一步的画面检查、调整一步的超时，之后回放仍然成功。
- **E2** `uv run pytest` 全部通过（不需要手机）。

## 验收步骤

```bash
uv run jevagent check                      # A1
uv run jevagent record S1-商店来回           # B1：录完看报告
uv run jevagent play S1-商店来回 --times 10  # C1
uv run jevagent list                       # 成功次数
```

D1–D4 和 E1 照上面的描述手动操作。每次回放的报告在 `data/flows/<名称>/runs/<时间>/report.html`，流程报告的"回放记录"里有汇总。

## 已知限制（M0 的设计边界）

- **只认得录制时见过的画面**。录制时没出现过的弹窗、活动公告、断线提示，都会让这一步等到超时后停止。手动关掉后从起点重来。
- **按钮背后的页面会变**（例如商店记住上次的页签）：锚点按轮廓比较，按钮本身没变就认得出来；按钮本身换了文字或图标时会停下。
- **锚点只说明"这里有这个东西"，不说明它的状态**。按钮从可领取变成已领取（比如只是变灰）时，可能仍被认作同一个按钮。领取类流程要看 C2 的人工确认，状态判断留给 M1。
- **内容每天变化的位置**（每日刷新的商品、随机奖励图标）锚点会对不上。对这些步骤用 `edit --set N.check=off`，它们会按录制节奏执行。
- 换手机、改显示分辨率或横竖屏比例后需要重录。分辨率变化但比例不变时会按比例缩放，但没有在真机上验证过。
- 回放默认比你录制时快（锚点出现就动手）。个别按钮如果在动画结束前不响应，用 `edit --set N.delay=秒数` 让它先等一会。

## 之后：M1

M1 处理"画面和录制时不一样"时该怎么办，以及更复杂的任务。M0 已经提供的基础：

- **流程 + 锚点**：每一步都知道"应该看到什么"，失败时知道"卡在哪一步、看到的是什么"。
- **判断点**：锚点等不到的那一刻，正是需要判断的时候（是弹窗就关掉、在加载就再等、不认识就停）。
- **可复用的子流程**：可以把"关闭某种弹窗"录成独立流程，由判断结果决定是否调用。

判断由谁来做：

- **LLM**（能看截图）：可以直接理解陌生画面，但慢、需要联网、有费用。
- **Jev**（TypeSafe API）和 **Laya**（laya-mlx，本地 ~10 ms）：回答结构化的选择题，但只接受文本状态。用它们需要先把画面转成文字，例如"当前能匹配到的锚点：关闭按钮、领取按钮"，或者 OCR 结果，再让它在"关闭弹窗 / 再等 / 停止"里选一个。中文输入要用 multilingual 检查点。

旧版浏览器研究模式的 Jev 调用方式在提交 `1f3f76f` 的 `server/policy.ts`，接 Jev 时可以参考。
