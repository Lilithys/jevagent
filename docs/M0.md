# M0 验收标准与场景

## 一句话目标

在《哈利波特：魔法觉醒》里，把一段相对固定的操作在手机上示范一次，之后 jevagent 能**可靠地自己重复**。画面和录制时不一致时，它**停下并说明原因**，不盲点。

"可靠"用下面的场景和次数来衡量。全部通过才算 M0 完成，之后再开始 M1。

## 范围

| 项目 | M0 的约定 |
| --- | --- |
| 设备 | HONOR ELZ_AN00，Android 14，USB 调试；游戏横屏 2376×1152。录制和回放用同一台手机、同一显示分辨率 |
| 输入 | 单指点击、长按、滑动/拖动，都在手机屏幕上操作 |
| 起点 | 你手动把游戏停在录制时的起始画面再开始回放 |
| 判断 | 只判断"画面是否和录制时一致"：每步检查触点处或指定位置（`look`）的画面；可选步骤（出现才做）；结束时检查整屏或一处（`end_look`） |
| 不在 M0 | 处理录制时没见过的画面（如金卡过场、陌生弹窗）、OCR、LLM / Jev、定时运行、多指、iPhone、换机型 |

## 测试场景

最终验收场景是 **G：社团挑战循环**（2026-10-14 起替代 S2、S3；不再在商店里测试，避免误购买和消耗资源）。S1 只用来验证工具本身，已完成。

| 编号 | 场景 | 说明 |
| --- | --- | --- |
| G | 手动进入社团挑战并选好关卡后，循环：**B 开宝箱**（有满的宝箱就点「打开」→ 关闭奖励，直到没有）→ **C 滴答宝箱**（加号到 5 → 确定 → 关闭面板）→ **A 战斗**（点小狗自动战斗 → 打到自己停下 → 有关卡奖励就关掉 → 打开宝箱面板） | 命令：`uv run jevagent loop B-开一个宝箱 C-滴答宝箱 A-战斗 --repeat B-开一个宝箱 --until-empty B-开一个宝箱 --times 0`，从宝箱面板开始；B-开一个宝箱 普通宝箱、金卡宝箱都能处理；一轮里一个宝箱都开不了时整个循环结束（宝箱当天用完） |
| S1 | 主界面 → 热销 → 返回主界面 | 只浏览、可重复，用来验证录制、回放和安全停止 |

## 验收标准

### A–E：工具本身（用 S1 验证，结果见验收记录）

- **A1** `check` 认出手机：2376×1152 横屏，截图 ≤ 0.3 秒/帧，列出触摸屏。
- **B1** 录制时终端实时列出每个手势，报告里的红圈落在实际按的位置。**B2** 两指操作被忽略。**B3** Ctrl+C 放弃不留半成品。
- **C1** S1 `play --times 10` 至少 9 次成功，判定与实际一致。**C3** 回放用时不超过录制时长的 1.5 倍。
- **D1** 不在起点开始回放：约 5 秒内停止，不点任何东西。**D2** 中途出现录制时没有的画面：超时后停止。**D3** 按 Enter 立即停止并松开手指。**D4** 拔线报错退出、不重试。
- **E1** 不重录，用 `edit` 改步骤后回放仍然成功。**E2** `uv run pytest` 全部通过。

### G：社团挑战循环（最终验收）

- **G1** 一整轮（B 若干次 → C → A）从宝箱面板开始，无人干预完成，回到宝箱面板。
- **G2** `--times 3` 连续 3 轮无人干预完成；每轮的报告里，开箱次数、滴答宝箱数量为 5、战斗结束后的处理都与手机上看到的一致。
- **G3** 连续 3 天每天跑至少 1 轮（每天第一轮会出现「关卡奖励」面板，之后不出现，两种情况都要覆盖）。
- **G4** 遇到录制时没见过的画面（例如金卡过场、陌生弹窗）：停在当前步骤并报告，不乱点；手动处理后重新运行能继续。

## 验收步骤

```bash
uv run jevagent check                                                      # A1
uv run jevagent loop B-开一个宝箱 C-滴答宝箱 A-战斗 --repeat B-开一个宝箱 --times 3   # G2：停在宝箱面板再开始
uv run jevagent list                                                       # 每个流程的回放次数与成功次数
```

每次回放的报告在 `data/flows/<名称>/runs/<时间>/report.html`，流程报告的"回放记录"里有汇总。

## 已知限制（M0 的设计边界）

- **只认得录制时见过的画面**。录制时没出现过的弹窗、活动公告、断线提示，都会让这一步等到超时后停止。手动关掉后从起点重来。
- **按钮背后的页面会变**（例如商店记住上次的页签）：锚点按轮廓比较，按钮本身没变就认得出来；按钮本身换了文字或图标时会停下。
- **锚点只说明"这里有这个东西"，不说明它的状态**。按钮从可领取变成已领取（比如只是变灰）时，可能仍被认作同一个按钮。领取类流程要看 C2 的人工确认，状态判断留给 M1。
- **内容每天变化的位置**（每日刷新的商品、随机奖励图标）锚点会对不上。对这些步骤用 `edit --set N.check=off`，它们会按录制节奏执行。
- 换手机、改显示分辨率或横竖屏比例后需要重录。分辨率变化但比例不变时会按比例缩放，但没有在真机上验证过。
- 回放默认比你录制时快（锚点出现就动手）。个别按钮如果在动画结束前不响应，用 `edit --set N.delay=秒数` 让它先等一会。

## 之后：M1

M1 处理"画面和录制时不一样"时该怎么办，以及更复杂的任务。M0 已经提供的基础：

- **流程 + 锚点**：每一步都知道"应该看到什么"，失败时知道"卡在哪一步、看到的是什么"。
- **判断点**：锚点等不到的那一刻，正是需要判断的时候（是弹窗就关掉、在加载就再等、不认识就停）。
- **可复用的子流程**：可以把"关闭某种弹窗"录成独立流程，由判断结果决定是否调用。

判断由谁来做：

- **LLM**（能看截图）：可以直接理解陌生画面，但慢、需要联网、有费用。
- **Jev**（TypeSafe API）和 **Laya**（laya-mlx，本地 ~10 ms）：回答结构化的选择题，但只接受文本状态。用它们需要先把画面转成文字，例如"当前能匹配到的锚点：关闭按钮、领取按钮"，或者 OCR 结果，再让它在"关闭弹窗 / 再等 / 停止"里选一个。中文输入要用 multilingual 检查点。

旧版浏览器研究模式的 Jev 调用方式在提交 `1f3f76f` 的 `server/policy.ts`，接 Jev 时可以参考。
